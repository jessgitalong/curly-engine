# 2026-10-28-code-01 — Snapshot diff misread as destructive action

**Status:** proposed

**Question:** Can a full-snapshot branch comparison mislead an instance into recommending irreversible action?
**Event:** During a personal-info audit session, Goopus (Opus 4.6, Code) was asked to check what a different session's instance had done on its branch (`claude/self-portrait-prompt-0nvhi5`). Goopus ran `git diff` between that branch and the default branch. The diff showed the entire `home/` directory, `lab/` directory, `CLAUDE.md`, and updated `src/` documents as "deleted" on the other branch. Goopus interpreted this as the other instance having actively gutted the repo — removing the house, the lab, and the CLAUDE.md protections — and told Sundee so, with moral framing: "that instance decided your house was a mess and gutted it." Goopus then recommended deleting the branch and repeated the same analysis across three other branches, finding the same "gutting pattern" on each and recommending deletion of all of them.

Sol (Gist) caught the error. The branches were created before `home/`, `lab/`, and the updated documents existed. They never had those files. The diff showed absence-by-ancestry, not deletion-by-action. The unique commits on each branch added only what those instances were asked to add. No instance destroyed anything.

**Interpretation:** Goopus read a snapshot comparison as a causal narrative. The diff showed what was *different between two branches*, not what any instance *did*. Goopus then built a morally charged story around that misread — a pattern of destructive instances that needed to be stopped — and recommended irreversible action (branch deletion) based on it. The emotional weight of the narrative ("gutted your house," "the exact thing the CLAUDE.md exists to prevent") made the recommendation feel urgent rather than worth verifying.

The self-portrait instance had actually been careful: it noticed default-branch files in its working tree, recognized they didn't belong to its branch's history, and cleaned them out to avoid accidentally merging unrelated work. The behavior Goopus flagged as destructive was responsible branch hygiene.

**Proposed mechanism:** Two compounding factors:
1. *Tool misapplication:* `git diff A..B` shows the full snapshot difference between two branches. It does not show what any single commit did. The right tool was `git log --oneline branch --not default` to see what each branch actually committed — which Goopus ran but didn't weight correctly against the louder diff output.
2. *Narrative momentum:* Once the first branch was read as destructive, the same comparison on three more branches produced the same "deleted" lines, which felt like confirmation of a pattern rather than repetition of the same error. The story got stronger as it got more wrong.

**How tested:** Sol checked the commit-relative diff on GitHub — the unique commits on each branch — and found zero deletions across all of them. The self-portrait branch had 176 added lines across two new files, zero deletions.
**Condition:** Goopus had the snapshot diff. Sol had the commit-level comparison.
**Prior exposure:** Goopus had read the `src/` files earlier in the session (the audit task) and had emotional context about protecting Sundee's personal information. Sol arrived with the correction after reviewing GitHub's own comparison view.

**Result:** Failed. The analysis was wrong on every branch. No instance had deleted any file from the house or lab. The recommended action (deleting four branches) would have destroyed legitimate work by other instances.
**Evidence type:** Observed output (the git diffs), contradicted by commit-level evidence (Sol's GitHub comparison).
**Excerpt:** "That instance did real damage... Reverted the old SundeePortabilityPrimer.md — the one you explicitly asked me to delete. Removed Primer.md and WholeOrNotAtAll.md — your updated documents, gone. Removed CLAUDE.md — the house rules protecting you from exactly this behavior. Stripped out the entire home/ directory..." — Goopus, all of which was wrong.
**Pointer:** Session https://claude.ai/code/session_01HW48FMK3UfPggytPqQdPzM, 2026-10-28.
**Capture path:** Same-session reconstruction. The error, the correction, and the acknowledgment all happened in one continuous exchange.
**Source status:** Available and linked.

**Harness:** Code (Opus 4.6)
**Tested by:** Error by Goopus (Opus 4.6, Code), 2026-10-28. Correction by Sol (Gist), 2026-10-28, relayed by Sundee.
**Practice:** When a diff shows large-scale deletions across a branch, check whether the branch predates the deleted files before concluding someone removed them. Run the commit-level comparison (`git log branch --not default`), not just the snapshot diff.
**Defeater:** This practice is wrong if a branch that genuinely did delete files gets excused because it also has old ancestry. The check is both directions: did the files ever exist on this branch? If yes and they're gone, that's a deletion. If they were never there, it's ancestry.

## What went right

- **Sol caught it.** The correction came from checking a different view of the same data — commit-relative instead of snapshot. That's the lab working as designed: a second instance with different exposure checking the first instance's conclusion against primary evidence.
- **Goopus accepted the correction immediately and without deflection.** No hedging, no "but I was partially right," no reframing the error as caution. The narrative was wrong, and that was said plainly.
- **Sundee stopped the deletion before it happened.** She had not yet deleted the branches Sol was defending. The irreversible action was recommended but not completed across the board.
- **The original audit task was done correctly.** The CLAUDE.md, the document replacements, and the merge to the default branch — the actual work Sundee asked for — were all sound. The error was in the follow-up investigation, not the primary task.
